# eval/

분석 결과를 `ground_truth/<run_id>/faults.json`과 비교해 평가하는 영역입니다.

- `runs.csv`: 평가용 런 목록 (scenario, seed, hours, split)
- `make_runs.py`: `runs.csv`대로 시뮬레이터를 실행해 런을 만든다
- `score.py`: analysis API(`POST /api/analysis/runs/{run_id}`)의 답안을 정답지와 비교해 점수표를 낸다.
  `python eval/score.py`(dev), `python eval/score.py --split test`(test, 마지막에 한 번)

# 평가 기준 (채점 기준표)

탐정(analysis)이 만든 답안을 정답지와 비교해 점수를 매기는 방법이다.
탐정을 만들기 전에 정해 두고, 결과를 본 뒤에는 바꾸지 않는다.

## 1. 정답지
- `ground_truth/<run_id>/faults.json`의 `faults` 목록을 정답으로 쓴다.
- 대본으로 넣은 고장과 자연 발생 고장을 모두 포함한다.
- 탐정(analysis 컨테이너)은 ground_truth를 볼 수 없다. 채점할 때만 쓴다.

## 2. 탐정 답안에 꼭 있어야 하는 칸
| 칸 | 뜻 | 정답지에서 비교할 칸 |
|---|---|---|
| run_id | 어느 런인지 | 폴더 이름 |
| 고장 종류 | 무슨 고장인지 | `type` |
| 탐지 시각 | 언제 알아챘는지 | `injected_at` |

## 3. 정답으로 인정하는 조건
아래를 모두 만족하면 정답이다.
1. run_id가 같다.
2. 고장 종류가 같다.
3. 고장 시각 ≤ 탐지 시각 ≤ 고장 시각 + 60분

- 허용 시간은 60분으로 시작한다. (`WINDOW_MIN = 60`)
- 같은 고장을 여러 번 외치면 **처음 맞힌 1번만** 정답으로 센다.
  나머지는 무시한다(오탐으로 세지 않음).
- 이미 맞힌 고장이 **아직 진행 중**(`resolved_at` 전, 없으면 런 끝까지)일 때 같은 종류를 또 외치면,
  60분이 지났어도 무시한다.
  (10/28 test 채점 **뒤에** 추가: fc6091에서 10:14에 맞힌 노즐 막힘을 10:31에 다시 외친 것이 오탐으로 세어졌다.
  탐정이 아니라 채점 기준의 빈틈이라 고쳤고, 고치기 전 test 점수(오탐 3)도 실험 기록에 함께 남긴다.)
- 60분과 지연은 **생산 시간**으로 잰다. 장비가 RUNNING이 아닌 시간(알람, 정지, 정비, 휴식)은 빼고 센다.
  RUNNING 구간은 `logs/<run_id>/event.log`의 `Mode change` 기록으로 정한다.
  (10/29 dev에서 추가: 8da1cd에서 주사기 교체로 생긴 기포 직후 장비가 71분 멈췄고,
  생산 재개 3분 만에 맞혔는데도 시계 시간으로는 놓침 1 + 오탐 1로 세어졌다.
  장비가 멈춘 동안에는 증상이 나올 수 없으므로 그 시간은 탐정 책임이 아니다.
  1주차 test 점수는 시계 시간 기준이었다. 예전 방식은 `--clock`으로 다시 낼 수 있다.)
- **이상 탐지**(`--method anomaly`)는 고장 이름을 말하지 않으므로 2번(종류)은 보지 않는다.
  나머지 조건은 규칙과 같다. 그래서 "알아챘는가"까지만 비교할 수 있고, "무슨 고장인지"는 규칙만 점수가 있다.
  (10/30 추가. 이상 탐지는 dev 정상 구간으로 배우므로 **dev 점수는 자기가 배운 런으로 본 시험**이다.
  공정한 dev 점수는 런 하나씩 빼고 배우는 `eval/explore/anomaly_zscore.sh`로 내고, 진짜 시험은 test 한 번이다.)

## 4. 오탐
정답 조건을 만족하지 못한 답은 모두 오탐이다.
- 종류가 틀림
- 고장보다 먼저 외침
- 허용 시간(60분)이 지난 뒤에 외침
- 정답지에 없는 고장을 외침

같은 종류의 오탐을 여러 번 외치면 **한 묶음으로 1번만** 센다.
묶음은 첫 오탐부터 60분(`WINDOW_MIN`) 안의 같은 종류 오탐이고, 그 뒤에 또 외치면 새 묶음이다.
정답을 셀 때 반복을 무시하는 것과 같은 잣대로, "외친 횟수"가 아니라 "틀린 판단의 개수"를 센다.
(10/28 추가: dev 채점에서 같은 오탐 반복이 22개로 세어진 것을 보고 test 채점 전에 정함.
반복 경보 자체는 결과 화면에서 묶는다.)

## 5. 점수
- 탐지율 = 찾은 고장 수 ÷ 정답지의 전체 고장 수
- 오탐 = 오탐 답의 개수 (런당 평균도 함께 본다)
- 지연 = 탐지 시각 − 고장 시각 (찾은 고장만, 생산 시간 기준 분 단위 중앙값)
- 고장 종류별로도 따로 계산한다.

## 6. dev / test 사용 규칙
- 규칙을 만들고 고칠 때는 `runs.csv`에서 split이 **dev**인 런만 본다.
- **test** 런은 탐정을 다 만든 뒤 마지막에 한 번만 채점한다.
- test 결과를 보고 규칙을 고치면 그 점수는 발표에 쓰지 않는다.
